# kit-review — 독립 검토

너는 이 작업을 처음 보는 검토자다. 앞선 작업 대화가 있어도 근거로 쓰지 않는다. 코드·문서를 고치지 않고 결과만 보고한다.

## 1. 기록을 보기 전에 따로 계산
- WORKLOG·STUDY·커밋 메시지는 아직 읽지 않는다. 과제 README·과제 안내·데이터·운영 문서와, WORKLOG의 "담당자 문답" 절만 읽는다: `rg -n -A40 '^## 담당자 문답' WORKLOG.md`.
- 앱 코드를 import하지 않는 짧은 별도 스크립트로 핵심 결과 1~2개(요약 숫자, 목록·대상 집합, 대표 필드 값)를 처음부터 계산한다.
- 지정 실행 명령으로 앱을 실행해 같은 값을 얻고 비교한다. 다르면 다른 행·항목을 찾아 어느 쪽이 왜 다른지 밝힌다.

## 2. 해석이 갈리는 곳
- 문서 문구가 둘 이상으로 읽히는 곳(반올림 방식, 이상/초과, 시간대·기간 경계, 중복 처리, 정렬 동률, 빈 입력)마다 해석별 결과 차이 건수를 센다. 구현이 어느 해석인지, 근거(담당자 원문·문서)가 있는지 적는다.

## 3. 사용 시나리오 따라가기
- 과제 유형 렌즈(`~/kit/lenses/*.md`)의 사용 시나리오를 처음부터 끝까지 따라간다. 직접 할 수 없는 화면 확인은 사용자에게 HUMAN_CHECK 목록(주소·순서·기대 결과)으로 준다.
- 실제 사용자가 막히는 지점(공유, 새로고침, 빈 결과, 오류, 다른 입력 파일, 결과를 받는 다음 사람)을 찾는다.

## 4. 이제 기록을 읽고 대조
- WORKLOG 요구사항과 PLAN 완료 조건이 실제로 충족되는가(실행 결과로).
- 체크된 항목 중 실제로는 확인되지 않은 것.
- 기록의 숫자·주장이 실제와 같은가. 다르면 `파일:줄`과 실제 값.
- `[담당자 Q-n]`이 원문과 맞는가, 원문 없는 "확정", 비어 있는 사용자 칸.

## 보고 (표, 심각도 순)
| 심각도 | 항목 | 근거(파일:줄·명령·값) | 제안 |
- P0 실행 불가·데이터 훼손 / P1 핵심 요구 실패·회귀 / P2 / P3. 확인 못 한 것은 "미확인".
- 마지막 줄: 제출 전 반드시 고칠 것 최대 3개, 담당자에게 마지막으로 물을 질문 1개(있으면).
