# kit-frame — 과제 파악과 담당자 질문

## 1. 읽기
- README·과제 안내·데이터·제출물 형식·지정 실행 명령·과제가 지정한 문서 이름을 확인한다. 과제 안의 점검 스크립트가 있으면 사용자에게 실행을 안내하고 새로 생긴 안내 문서를 읽는다.
- WORKLOG 사용 자료 칸에 kit 저장소 주소와 `git -C ~/kit rev-parse HEAD` 전체 해시를 적는다. 모델은 사용자에게 묻는다.

## 2. 렌즈
- 유형을 고른다: 데이터 처리 / 웹 서비스·화면 / 기존 코드 수정 / 원인 분석(섞이면 두 개). `~/kit/lenses/<data|web|codefix|analysis>.md`를 읽는다.

## 3. 요구와 함정 (데이터·코드로 센다, 추측 금지)
- 요구마다 R 번호, 출처(`파일:줄`), 수용 기준을 WORKLOG "요구사항" 표에.
- 단서 문장을 빠짐없이 뽑는다: 문서에서 "다만·단·예외·제외·포함·이상·미만·초과·이후·이전·변경·주의"가 든 문장을 `파일:줄`과 원문으로 나열하고, 각각 어느 R·함정에 연결되는지 적는다. 연결되지 않는 단서는 함정 후보로 올린다.
- 개인정보·비밀정보 열(이름·연락처·사번 등)이 있으면 알리고 다루는 방식을 제안한다.
- 함정 상위 6개: 근거 위치, 영향 건수, 예시 1개, "문서로 확정 / 데이터로 확정 / 담당자만 앎".
- 반드시 세는 것: 반올림 표시가 있으면 반올림 전 값이 .x5 경계에 걸리는 건수와 사사오입·`round()` 결과가 다른 건수, 기준값과 정확히 같은 값의 건수. 해석이 갈리면 WORKLOG "해석이 갈리는 곳"에 해석별 차이 건수를 적는다.

## 4. 담당자 질문 (사용자가 직접 보낸다)
- 사용 방식 질문 2개는 영향 건수와 상관없이 반드시 넣는다(렌즈에서 고름).
- 이어서 "담당자만 앎" 함정 질문 최대 4개: 한 질문에 하나, 대상 건수, 답이 없을 때의 기본 해석.

## 끝
- "지금" 갱신, 커밋 `frame: 요구 n개, 함정 n개, 질문 n개`. 다음: 답 원문을 붙여 넣고 `$kit-plan`.
