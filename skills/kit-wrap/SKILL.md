# kit-wrap — 인계와 서술형 리허설

제출을 확정한 뒤라면 아무것도 하지 않고 "확정 뒤에는 쓰지 않습니다"라고만 답한다.

## 1. 동결과 제출물 대조 (10분 이내)
- 새 기능을 멈춘다. 반쯤 만든 기능은 끄고 한계에 적는다.
- 과제가 요구한 파일·문서·형식·경로·실행 명령과 한 줄씩 대조한다. 지정 명령으로 처음부터 실행하고 전체 테스트를 돌려 숫자로 보고한다.
- `python3 ~/kit/bin/check.py`를 한 번 실행한다. 사실 오류와 빈칸만 고치고, 표현 다듬기에 시간을 쓰지 않는다.
- PLAN "마무리 체크"를 갱신한다.

## 2. 인계 문서 (과제가 지정한 이름, 없으면 HANDOFF.md, 2쪽 이내)
- 맨 위: 결론과 핵심 숫자, 확인한 것 / 못 한 것.
- 실행 방법, 동작 방식(WORKLOG "동작 흐름"의 사용자 문장 바탕), 정의와 근거(R·Q·D), 데이터를 거르거나 바꾼 단계와 건수, 해석이 갈리는 곳과 적용한 해석, 검증(실제 명령·결과), 한계·미확정과 다음 사람이 먼저 볼 것, 사용한 공개 도구(kit 저장소와 용도 한 줄).
- WORKLOG·STUDY의 내용을 옮기되 같은 말을 반복하지 않는다.

## 3. 숫자 카드 (STUDY.md 맨 위 표, 실행해서 채운다)
- 처리 단계별 건수, 핵심 결과 숫자
- 해석을 바꾸면 달라지는 숫자(해석 표의 항목마다)
- 기준값을 바꾸면 고칠 곳 `파일:줄`과 바뀐 숫자(문턱을 낮추는 경우·올리는 경우를 각각 실행, 늘어나는 항목 ID까지)
- 대표 예시 2~3건과 그 값

## 4. 서술형 리허설 (사용자가 직접 답한다 — 가장 중요)
- 실제 기록에 맞춘 질문 6개를 하나씩 낸다:
  ① 처음 코드·데이터가 왜 틀렸나, 각각 어떻게 고치고 무엇으로 확인했나
  ② 다른 기준·다른 시스템과 숫자가 왜 다른가, 어느 쪽이 맞는지 어떻게 확인하나
  ③ 반대 해석이었다면 무엇이 몇 건 바뀌나
  ④ 데이터를 거르거나 바꾼 단계와 건수, 테스트 기대값의 근거
  ⑤ 기준 변경 요청 시 고칠 곳, 숫자 변화, 회귀 확인 방법(경계 직전·정각·직후 + 기존 기준)
  ⑥ AI 결과를 고치거나 다시 시킨 사례와 판단 근거
- STUDY에서 "미답"이거나 교정을 받은 질문은 반드시 다시 묻는다.
- 사용자가 결론 → 근거(파일:줄·담당자 원문) → 숫자 → 파급 → 다음 행동 순서로 답하면 사실 오류와 빠진 숫자만 짚는다. 틀린 답은 사용자가 고쳐 쓰게 하고 다시 확인한다. 사용자의 답이 구현과 다르면 그 차이를 가장 먼저 알린다.
- 문답(질문 / 내 답 원문 / 사실 확인 / 고쳐 쓴 답)을 STUDY "서술형 리허설" 절에 남긴다.

## 5. 마무리
- 커밋 `wrap: 인계·숫자 카드·리허설 / 확인: 전체 테스트 n passed`. `git status`가 비었는지 확인한다.
- 안내: 저장 상태 확인 → 제출 시작. 이후 새 작업은 시작하지 않는다.
