# kit-wrap — 인계와 설명 리허설

제출을 확정한 뒤라면 "확정 뒤에는 쓰지 않습니다"라고만 답한다.

## 1. 동결과 대조 (10분 이내)
- 미확정·답 대기로 열어 둔 항목이 있으면 먼저 AGENTS.md의 미확정 규칙대로 문서 문장으로 정할 수 있는지 확인한다. 정할 수 있으면 사용자에게 알리고 동결 전에 구현한다.
- 새 기능을 멈춘다. 과제 요구 파일·형식·실행 명령과 대조하고, 지정 명령으로 처음부터 실행, 전체 테스트를 돌려 숫자로 보고한다.
- `python3 ~/kit/bin/check.py`를 한 번 실행해 사실 오류와 빈칸만 고친다. PLAN 마무리 체크를 갱신한다.

## 2. 영향 숫자 (REVIEW_NOTES, 실행해서 채운다 — 유형마다 1줄 이상)
1. 원인과 수정: 원인별 고친 `파일:줄`과 확인 테스트
2. 다른 기준과의 차이: 다른 기준으로 계산한 숫자와 차이 나는 항목 ID
3. 반대 해석: 해석 표 항목마다 바뀌는 숫자(반올림 경계 포함)
4. 처리 단계별 전·후 건수
5. 기준 변경: 기준값마다 고칠 `파일:줄`, 문턱을 낮출 때·올릴 때 바뀌는 숫자와 항목 ID
6. AI 결과를 고친 사례: 무엇이 이상했고 무엇으로 확인했나
- 검토 질문의 빈 근거도 채운다.

## 3. 쉬운 설명서 (GUIDE.md)
- `~/kit/prompts/guide.md`를 읽고 그대로 따라 GUIDE.md를 만든다(2쪽 이내, 실행해서 맞춘 숫자, 쉬운 말).
- 사용자가 읽고 이해 안 되는 줄을 짚으면 더 쉽게 고쳐 쓴다. "내 판단"이 빈 검토 질문은 이때 사용자가 한 줄씩 쓰게 한다.

## 4. 인계 문서 (과제 지정 이름, 없으면 HANDOFF.md, 2쪽 이내)
- GUIDE·WORKLOG를 바탕으로 쓰되 같은 문장을 반복하지 않는다.
- 맨 위: 결론과 핵심 숫자, 요구별 충족 표(R / 충족·부분·누락 / 근거 `파일:줄`·테스트, 누락이면 이유). 누락이 있으면 사용자에게 먼저 알린다.
- 이어서 실행 방법, 정의와 근거(R·Q·D), 거르거나 바꾼 단계와 건수, 적용한 해석(반올림 방식 포함), 검증(실제 명령·결과), 한계·미확정, 사용한 kit 주소·전체 해시·모델.

## 5. 리허설 (사용자가 직접 답한다)
- 검토 질문을 이번 과제의 코드·숫자·항목 ID를 넣은 구체 질문으로 바꿔 6개를 하나씩 낸다. 6개 안에 반드시 넣는다: ① 미해결·미확정으로 남긴 항목 ② AI가 만든 검증 도구가 무엇을 증명하고 무엇을 못 하나(공유 가정) ③ 바꾼 기존 테스트와 그 근거. "바로잡은 이해"는 전부 다시 묻는다.
- 답은 결론 → 근거 → 숫자 → 파급 → 다음 행동 순서로. 사실 오류와 빠진 숫자만 짚고 고쳐 쓰게 한다. 새로 틀린 것은 "바로잡은 이해"와 GUIDE "헷갈리기 쉬운 것"에 추가한다.

## 6. 마무리
- 커밋 `wrap: GUIDE·인계·영향 숫자·리허설 / 확인: 전체 테스트 n passed`, `git status`가 비었는지 확인.
- 안내: 제출 직전 GUIDE.md 하나만 처음부터 끝까지 한 번 더 읽는다. 이후 새 작업은 시작하지 않는다.
