# kit-build — PLAN 한 단계

## 1. 시작
- 사용자가 고른 단계(없으면 첫 "대기" 단계)의 체크리스트를 보여 주고 상태를 "진행"으로 바꾼다.
- 숫자·판정이 나오는 단계면 먼저 묻는다: "실행 전에 결과를 예상해 주세요(대략이면 됩니다)."

## 2. 구현과 확인
- 기준값은 상수 한 곳에. 요청에 없는 기능은 만들지 않는다.
- 완료 조건을 하나씩 실제로 실행해 확인한 것만 체크한다. 전체 테스트와 지정 실행 명령까지 돌린다.
- 화면·결과물은 볼 것(주소·순서·기대 결과)을 알려 주고 사용자가 확인한 뒤 체크한다. 예측과 다르면 원인부터 설명한다.
- 사람 검산: 이 단계 결과에서 중간값 하나를 그 값을 만든 원자료 행(`파일:줄`)과 함께 보여 주고, 사용자가 원자료를 직접 보고 맞는지 답하게 한다. 사용자의 확인은 커밋 메시지에 `사용자 확인: …`으로 남긴다.

## 3. 담당자에게 보낼 것 (초안만 쓰고, 보내는 건 사용자)
- 기준이 모호해 결과가 갈리고 문서·문답으로 정할 수 없으면 추측하지 말고 질문 초안 1개를 준다: 질문 한 문장, 대상 건수·예시 ID, 답이 없을 때 적용할 기본 해석. 이미 [미확정]인 질문은 다시 내지 않는다.
- 중간 공유: S1(첫 완주)이 끝나면, 그리고 기능 동결 전에 한 번 더, 담당자에게 보낼 3줄 메시지 초안을 준다: ① 지금 되는 것과 핵심 숫자 ② 확인 방법(실행 명령이나 화면에서 볼 곳) ③ "실제로 쓰실 때 더 필요한 게 있을까요?". 담당자 답에서 새 요청이 나오면 R과 PLAN 할 일로 추가하고 알린다.

## 4. 기록
- WORKLOG: 체크박스, 상태 `완료 <커밋>`, "지금", 요구사항 상태, 해석·데이터 처리 표의 최신값을 덮어쓴다. 150줄이 넘으면 완료 단계의 할 일을 한 줄로 접는다.
- REVIEW_NOTES "검토 질문"에서 이 단계로 답할 수 있게 된 칸의 근거(`파일:줄`·숫자·항목 ID)만 채운다.

## 5. 이해 보고 (채팅으로, 쉽게, 실제 값으로)
1. **한 일과 예시**: 무엇을 왜 바꿨나(`파일:줄`), 실제 1건이 입력 → 중간 값 → 결과로 가는 길
2. **헷갈리는 점과 반대였다면**: `오해 → 사실` 1~2개, 다른 해석·이전 코드였다면 바뀌는 숫자(실행한 값)
3. **판단 한 줄 요청**: 검토 질문에서 이 단계와 맞는 질문 하나를 골라 "판단을 한 줄로 써 주세요". 사용자 답은 "내 판단" 칸에 원문 그대로, 틀린 사실은 바로잡고 "바로잡은 이해"에 추가한다.
- S1 뒤에는 입력 → 처리 → 출력 흐름을 파일 이름과 함께 3줄로 써 달라고 해서 WORKLOG "동작 흐름"에 옮긴다.
- 사용자가 전체 흐름이 헷갈린다고 하면 `~/kit/prompts/guide.md`를 따라 GUIDE.md를 만들거나 갱신한다.

## 6. 커밋
- 코드·테스트·WORKLOG·REVIEW_NOTES를 한 커밋으로: `S2: 무엇 / 확인: 명령 → 결과`. 다음 대기 단계를 제안하고, 모두 끝났으면 새 세션 검토(`~/kit/prompts/review.md`)를 제안한다.
