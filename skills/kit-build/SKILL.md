# kit-build — 체크리스트를 다 채우면 끝

## 끝나는 조건 (이것만 본다)
PLAN.md 7절의 모든 항목이 `[x]` 또는 `[-]`(버린 이유)가 되고, F6 최종 보고를 했을 때. **그 전에는 턴을 끝내지 않는다.** 블록이 끝날 때 보고하고 기다리지 말고 다음 칸으로 간다.

## 시작
- HANDOFF.md가 있으면 먼저 읽는다(끊긴 뒤 다시 부른 경우). 그다음 PLAN.md 1절·4~7절.
- `[ ]`인 첫 항목부터 시작한다.

## 항목 하나를 할 때
1. 만든다. 기준값(정원·상한·가중치 등)은 설정 한 곳에 모은다. 체크리스트에 없는 기능은 만들지 않는다.
2. 확인 칸의 명령을 **실제로 실행**한다. 테스트를 쓰고 돌린다. 실패하면 원인부터 찾는다.
3. 데이터를 거르거나 바꾸는 곳이면 전후 건수·사유를 정제 장부에 남긴다.
4. PLAN.md 그 줄을 `[x] … — 커밋 abc1234 · 결과: 숫자`로 바꾸고 경로를 지정해 커밋한다.
5. 채팅에는 한 줄만: `B03 끝 — 확인 결과 숫자`.

## 블록이 끝날 때
- GUIDE.md 2절 "기능별 카드"에 그 블록의 카드를 추가한다(`.agents/kit/templates/GUIDE.md` 양식). 코드가 바뀐 곳의 기존 카드도 고친다.
- HANDOFF.md를 갱신한다: 지금 상태 / 끝난 항목·버린 항목 / 최근 확인 숫자 / 남은 문제 / 가정 / 다음 항목.

## 멈추지 않는다 — 대신 이렇게
| 상황 | 하는 일 |
|---|---|
| 해석이 갈리는 선택 | 문서 문장에 가장 가까운 쪽으로 정하고 진행. PLAN 5절 가정에 추가 |
| 같은 실패 2번 | 그 항목을 `[-] 막힘: 처음 어긋난 지점 한 줄`로 두고 다음 항목. P0이면 더 단순한 방법으로 한 번 더 |
| 패키지 설치 실패 | 다시 시도하지 말고 표준 라이브러리로. PLAN 1절에 "패키지 설치: 막힘" |
| 화면을 사람이 봐야 함 | 멈추지 않는다. REVIEW.md에 확인할 것으로 적는다 |
| 사용자가 중간에 말함 | 지금 항목을 끝낸 뒤 AGENTS.md "사용자가 중간에 말할 때"대로: 바로 반영 → 새 항목을 남은 항목 앞에(규칙이면 E1 기대값에도), 기록 → MEMO.md에 원문 그대로 한 줄 |
| 사용자가 "마무리해" | 지금 항목을 끝내고 남은 P2·P1을 `[-] 버림: 사용자 요청`, 바로 E로 |
| 사용자가 AI 결과를 고치거나 막음 | 따르고 "MEMO.md '내가 AI를 고친 순간'에 남길까요? '기록해 둬'라고 하시면 적겠습니다" 한 줄 |

멈추고 묻는 경우는 하나뿐: 되돌리기 어려운 작업(원본 삭제·외부 전송 등)의 해석이 갈릴 때.

## E. 자기 검토 (버리지 않음)
같은 세션이라 완전히 독립적이지 않다. 그래서 **앱 코드를 import하지 않는** 방법으로 확인한다. 도구가 하위 에이전트(서브 에이전트)를 지원하면 E1은 README·담당자 표만 준 하위 에이전트에게 맡긴다.
- E1 `evidence/independent_check.py`: README·스키마·PLAN 4절 담당자 원문만 보고 짠 검사기로 내보내기 결과의 규칙 위반을 센다. 앱과 같은 가정을 공유한 곳은 결과에 적는다.
- E2 PLAN 1절 터미널 종류로 실행 안내를 **그대로** 따라 빈 상태에서 시작한다. 사용자가 서버를 켜 두었을 수 있으니 임시 폴더의 새 DB와 비어 있는 다른 포트를 쓰고, 사용자의 서버·DB는 건드리지 않는다. `/health` 확인 뒤 끈다.
- E3 역할별로 실제 요청을 보낸다: 로그인 → 핵심 기능 → 결과 → 내보내기. 남의 권한 요청은 서버가 거절하는지. 로그인이 있으면 쿠키 없이도 유지되는지(미리보기 창).
- E4 데이터셋 기능이 있으면: 정상 변경 적용 → 결과가 바뀜 / 잘못된 데이터셋 → 무엇이 틀렸는지 안내 + 기존 결과 유지 / 적용 뒤 재계산 전 옛 결과를 새것처럼 보이지 않음.
- E5 `.agents/kit/design/web-service.md` 점검표("항상 필수" 전부 + 이번에 만든 "요구할 때만")를 PASS/FAIL/미확인으로 `evidence/ops-check.md`에.
- E6 요구 표의 R마다 됨/일부/안 함(이유).
- E7 E1~E6에서 나온 P0(실행 안 됨·데이터 훼손)·P1(규칙 위반·필수 요구 실패)을 **바로 고치고** 그 검사를 다시 돌린다. P2 이하는 HANDOFF "남은 문제"로.
- 사용자가 서두르라고 했으면 E1·E2·E3·E7만 하고 나머지는 최종 보고에 "남음"으로 적는다.

## F. 문서·공부 자료 (버리지 않음)
- F1 REVIEW.md: `.agents/kit/templates/REVIEW.md` 양식. 사용자가 직접 볼 순서, 계정, 클릭 순서, **정상이면 보이는 것(오류 문구 포함)**, 이상하면 적을 칸.
- F2 GUIDE.md 완성: 0절 5분 요약과 9절 서술형 카드를 실제 코드·실제 숫자로. 9절에는 함수 이름을 쓴다. 2절 카드가 코드와 맞는지 한 번 대조.
- F3 과제가 요구한 문서(실행 안내 등): 명령은 E2에서 실제로 돈 것만 쓴다.
- F4 AI 협업 문서 초안: MEMO.md "내가 AI를 고친 순간"과 커밋 기록에 있는 일만. 근거 없는 일반론 금지. 각 문장에 "어느 파일·무엇으로 확인"을 붙인다.
- F5 HANDOFF.md 최종 갱신. 다음 세션이 PLAN 대신 이것을 읽는다.
- 사용자가 서두르라고 했으면 F1·F2(0절·9절)·F5부터.

2. 자기 검토 숫자: 독립 검사 위반 수, 테스트 n passed, 실행 확인 여부, 미확인 목록
3. 가정 목록(이번 빌드에서 새로 생긴 것 표시)
4. 다음 할 일:

   - "터미널이 남으면 새 codex로 `$kit-check`를 부르면 검토를 하나 더 받습니다."
   - "기다리는 동안 GUIDE.md 0절과 9절부터 읽으세요."
