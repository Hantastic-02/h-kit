# kit-plan — 합의와 PLAN

## 1. 답 반영
- 담당자 답을 WORKLOG "담당자 문답"에 원문 그대로, Q 번호와 함께 적는다. 요구사항·해석 표·미확정을 고치고, 새 요청은 R로 추가해 알린다.

## 2. 합의
- 다섯 칸(문제 / 성공 기준(숫자) / 만들 것 / 안 만들 것과 이유 / 제약) 초안을 보여 주고 사용자가 자기 말로 고쳐 쓰게 한다. "그대로"라고 하면 성공 기준과 안 만들 이유 두 칸만이라도 직접 써 달라고 한 번 더 요청한다.

## 3. PLAN (WORKLOG "PLAN" 절)
- 단계 4~7개. S1은 첫 완주(입력 → 제출물·핵심 화면까지 가장 단순한 경로). 이후는 가치·위험이 큰 요구부터.
- 단계마다: `### S2 이름 — 상태: 대기 — 예산 __분` / 목표·관련 R·Q / 할 일 체크박스(파일·함수 단위) / 완료 조건 체크박스(숫자나 관찰 가능한 결과) / 기대값 출처 / 사용자가 직접 볼 것.
- 렌즈 점검표(예: 웹 점검표) 항목을 알맞은 단계로 옮기고, 해석 표의 항목마다 테스트 할 일을 넣는다. 모든 R이 어느 단계에 들어갔는지 확인한다.
- PLAN 머리에 기능 동결·제출 시작 시각.

## 4. 검토 질문 시작
- REVIEW_NOTES "검토 질문" #1~#5의 근거를 채우고, 사용자에게 #1 판단을 한 줄로 받는다.

## 5. 승인
- 단계별 2줄 요약을 보여 주고 승인받는다. 승인할 때 사용자에게 "가장 위험한 단계와 이유"를 한 줄로 받아 결정 표에 적는다. 커밋 `plan: 합의·PLAN S1~Sn`. 다음: `$kit-build S1`.
- build 중 새 할 일은 해당 단계에 체크박스로 추가하고, 시간이 모자라면 뒤 단계를 `보류(이유)`로 바꾼다.
