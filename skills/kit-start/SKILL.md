# kit-start — 환경·자료·질문·문제 후보

결과는 PLAN.md 1~4절과 5절의 질문(`.agents/kit/templates/PLAN.md` 양식), 채팅의 질문 목록이다. 앱 코드는 만들지 않는다.
질문은 두 번에 나눠 낸다. 사용자가 첫 묶음을 보내는 동안 데이터를 센다.

## 1. 환경 (PLAN 1절)
- `git status`·`git log`가 실패하면: `git init` → `.gitignore`(`runtime/`, `__pycache__/`, `*.pyc`, `.env`) → 지금 있는 파일로 첫 커밋 `start: 과제 초기 파일`(이때만 전체 추가 허용).
- `python -V; node -v; docker -v`. 점검 스크립트(check_setup 등)가 있으면 실행을 안내하고, 새로 생긴 안내 문서도 읽는다.
- 사용자가 서버를 켤 터미널 종류(bash / cmd / PowerShell)를 한 줄로 적고 "다르면 알려 주세요"라고 붙인다.

## 2. 자료 파악 (PLAN 2절)
- README, 과제가 가리키는 문서, 데이터 파일 목록·행 수·열·기간, 제출물 목록을 읽는다.
- 요구 표(R): 기능 요구뿐 아니라 규칙·제출물·실행 조건·"하지 말 것"도 R로 넣는다. 결과 검증에 직접 쓰일 것에 ★.
- 담당자가 여러 명이면 이름·역할을 표로 적는다.
- 고칠 기존 코드가 있으면: 고치기 전에 그대로 실행해 결과를 `evidence/before/`에 저장하고, 기존 테스트를 돌려 결과를 적는다. 기존 테스트도 문서·담당자 답과 다를 수 있는 대상으로 본다.

## 3. 첫 질문 묶음 (바로 낸다)
아래 주제마다 이번 과제에 맞춘 질문 1개. 한 질문에는 한 가지만 묻는다. 해결 방법이 아니라 지금 상황을 묻는다. 데이터에 안 보여도 묻는다.
1. 지금 이 일을 누가, 어떤 순서로 하나 / 결과물을 몇 명이 함께(동시에) 쓰고 어떻게 넘겨 보나
2. 가장 불편한 점, 사람이 자주 틀리는 곳
3. 결과를 누가 받아서 다음에 무엇을 하나
4. 숫자 기준: 경계값 포함 여부(이상/초과), 단위, 반올림·절사, 하루의 시작 시각과 시간대(현지/UTC)
5. 최종 결론을 내는 규칙: 여러 항목·그룹의 결과를 어떻게 합쳐 판단하나, 몇 건부터 판단하나
6. 예외와 꼭 지킬 것: 특정 대상·기간·설비·고객에만 다른 규칙, 안전·법적 의무
7. 최근 바뀐 것: 규정·기준·시스템·이름
8. 기록 방식의 특이점: 다시 기록·정정·오류값·테스트용 데이터
9. 성공 기준: 무엇이 얼마나 좋아지면 되나
10. 범위 밖: 이번에 하지 않을 것
11. 담당자가 여럿이면: 이 과제와 각자의 일이 어떻게 연결되나, 넘으면 안 되는 선이 있나
- 질문마다 아래 괄호에 "답이 없을 때 쓸 기본 해석"(사용자에게만 보임).
- 낸 질문은 기본 해석과 함께 PLAN 5절에 주제별로 적어 둔다(답 칸은 비움). 두 번째 묶음도 같다.
- 안내 한 줄: "한 메시지에 하나씩 지금 보내세요. 그동안 데이터를 셉니다."

## 4. 데이터 신호 (PLAN 3절, 짧은 스크립트로 실제로 센다)
큰 파일은 한 줄씩 읽는 스크립트로 센다. 아래를 모두 훑고 나온 것만 표에 쓴다.
- 문서에 없는 값(상태·코드·범주)
- 빈 날짜·0인 구간, 갑자기 늘어난 기간
- 같은 키의 중복·다시 기록(시각만 다른 행)
- 극단값·자리 채움 값(누가 봐도 측정값이 아닌 값)
- 참조 누락 ID, 같은 이름 다른 ID
- 한 열 안에 단위·통화·척도가 섞임
- 기간 정의가 다른 행(회계 기간, 하루 시작 시각 등)
- 전체 평균에는 안 보이고 하위 그룹(설비·지역·유형별)에서만 보이는 변화 — 범주 열마다 나눠서 센다
- 문서에는 필요한데 데이터에 없는 기간이나 항목
- 문서 안의 예시·표·코드가 규칙 문장과 안 맞는 곳
- 표: `신호 | 건수 | 예시 1개 | 문서로 정해짐 / 담당자만 앎`.
- "담당자만 앎"마다 두 번째 질문 1개(건수·기간·예시를 넣고, 첫 묶음과 겹치면 뺀다).

## 5. 문제 후보 (PLAN 4절) — 무엇을 풀지 과제가 열어 둔 경우만
- 후보 2~3개 표: `누가 무엇 때문에 불편한가 | 근거 숫자 | 해결되면 좋아지는 숫자 | 이번 시간에 가능한가 | 위험`.
- 추천 하나와 이유. 결정은 사용자가 한다.
- 과제가 이미 정해져 있으면 "해당 없음"이라고 적는다.

## 끝
- 커밋: `start: 요구 R1~Rn, 신호 n개, 질문 n개`
- 안내 3줄:
  1. "질문은 한 메시지에 하나씩, 답을 기다리지 않고 연달아 보내도 됩니다."
  2. "'확인해 보겠다'는 답 없음입니다. 다음 질문으로 넘어가세요."
  3. "답을 원문 그대로 붙여 넣고 `$kit-plan`을 부르세요. 문제 후보가 있으면 고른 번호와 이유도 같이 주세요."
