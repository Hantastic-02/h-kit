# kit-start — 환경·문제 정의·담당자 질문

코드는 바꾸지 않는다. 결과는 `.agents/kit/templates/PLAN.md` 양식으로 PLAN.md 1~3절과 4절 질문 목록에 쓴다.
질문을 **두 번에 나눠** 내보낸다. 사용자가 첫 묶음을 보내는 동안 데이터를 센다.

## 1. 환경 (PLAN 1절)
- 저장소가 아니거나(`git status` 실패) 커밋이 하나도 없으면(`git log` 실패): 필요하면 `git init` → `.gitignore`(`runtime/`, `__pycache__/`, `*.pyc`, `.env`) → 지금 있는 파일로 첫 커밋 `start: 과제 초기 파일`(이때만 전체 추가 허용).
- `python -V; node -v; docker -v`.
- 사용자가 서버를 켤 터미널 종류: 너(Codex)의 셸과 다를 수 있다. Windows 연습장은 cmd(줄 앞이 `D:\...>`), Linux 시험은 bash가 기본이다. 보고에 "터미널: cmd로 적었습니다. 다르면 알려 주세요" 한 줄.
- 점검 스크립트(check_setup 등)가 있으면 실행을 안내하고, 새로 생긴 안내 문서도 읽는다.

## 2. README 읽기 → 첫 질문 묶음 바로 내기
- README, 과제가 가리키는 문서(스키마·데이터 설명), 데이터 파일 목록과 행 수, 제출물 목록을 읽는다.
- 곧바로 **운영 조건 10칸** 질문을 이번 과제에 맞춰 칸마다 1개씩 만들어 채팅에 낸다. 데이터에 안 보여도 묻는다(숨은 조건은 그 주제를 물어야 나온다).
  1. 사용 방식: 누가 언제 어떤 순서로 쓰나
  2. 결과 전달: 결과를 누구에게 어떻게 넘기나, 넘긴 뒤 바꾸면
  3. 안전·법규: 문서에 없지만 반드시 지켜야 하는 안전·표시·개인정보 규칙
  4. 일부 집단: 특정 구성원만을 위한 조건(식이·교대조·장애·직군 등)
  5. 일시 변경: 계획 기간에 설비·인력·장소가 평소와 다른 날
  6. 반복·공정: 같은 것을 몇 번까지 허용하나, 연속 금지가 있나
  7. 출처 편중: 데이터를 남기지 않는 사람들의 선호·상황은 무엇으로 보나
  8. 좋은 결과의 기준: 여러 목표가 부딪치면 무엇을 먼저 보나
  9. 숫자 기준: 여유율·상한·우선순위 숫자와 그 근거
  10. 범위 경계: 포함·제외가 애매한 대상(협력사, 신규 항목, 경계 날짜)
- 질문마다 아래 괄호에 **답이 없으면 적용할 기본 해석**(사용자에게만 보임).
- 안내 한 줄: "이 10개를 한 메시지에 하나씩 지금 보내세요. 그동안 데이터를 셉니다."

## 3. 문제 정의 (PLAN 2절)
- 한 문장 목표, 요구 표(R), 만들지 않을 것. README의 요구뿐 아니라 운영 규칙·제출물·실행 조건·"하지 말 것"도 R로 넣고 ★를 표시한다.

## 4. 데이터 신호 (PLAN 3절, 짧은 스크립트로 실제로 센다)
큰 파일은 한 줄씩 읽는 스크립트로 센다. 아래를 모두 훑고, 나온 것만 표에 쓴다.
- 문서에 없는 값: 상태·종류 값 중 설명서에 없는 것(예: 취소, 조회)
- 척도 변화: 같은 열의 값 범위가 날짜에 따라 달라짐(예: 어느 날부터 점수 만점이 바뀜)
- 날짜 공백·0인 날: 기록이 비거나 0인 날짜·장소
- 특정 기간 급증: 주별 건수가 평소의 2배 넘는 기간과 그때 몰린 항목
- 근접 중복: 같은 사람·같은 대상이 몇 초 안에 반복
- 참조 누락: 명단·목록에 없는 ID
- 이름 중복: 이름은 같은데 ID가 다른 항목
- 출처 편중: 기록을 남기는 사람이 특정 집단에 몰림(예: 앱 기록은 특정 직군만 남김)
- 문서에는 필요한데 데이터에 없는 기간(예: 직전 달 이력)

## 5. 두 번째 질문 묶음
- 3절 표의 "담당자만 앎" 항목마다 1개. 건수·기간·예시를 넣는다. 첫 묶음과 겹치면 뺀다.
  예: "○월 ○주에 ○○ 기록이 평소의 6배입니다. 이 주에 무슨 일이 있었나요?" (기본 해석: 행사 기간으로 보고 그 주를 빼고 계산)
- PLAN 4절에 첫 묶음과 두 번째 묶음을 번호대로 적는다(답 칸은 비워 둔다).

## 끝
- 커밋: `start: 요구 R1~Rn, 신호 n개, 질문 n개`
- 안내(3줄):
  1. "두 번째 질문도 한 메시지에 하나씩 보내세요. 답을 기다리지 말고 연달아 보내도 됩니다."
  2. "'확인해 보겠다'는 답 없음입니다. 다음 질문으로 넘어가세요."
  3. "답을 원문 그대로 붙여 넣고 `$kit-plan`을 부르세요."
