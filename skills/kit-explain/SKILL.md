# kit-explain — 서술형 연습과 마무리 커밋

제출을 확정한 뒤라면 "확정 뒤에는 쓰지 않습니다"라고만 답한다. 코드는 바꾸지 않는다(문서 오타·숫자 갱신만).

## 0. 읽기 (2분)
- HANDOFF.md → GUIDE.md 0절·9절 → AI 협업 문서 → 실행 안내. PLAN.md 전체는 읽지 않는다(필요한 절만 `rg`).
- GUIDE 숫자가 HANDOFF·최근 커밋과 다르면 다시 실행해서 고친다.

## 1. 예상 질문 만들기
실제 시험의 질문은 **내 제출물에서** 나온다: 문서에 쓴 설계 주장, 가정, AI 협업 문서의 문장, 핵심 함수의 흐름. 6유형을 이번 과제의 실제 파일·함수·숫자·사용자가 한 말을 넣어 만든다.

**먼저 할 4개** (함수 흐름을 묻는 유형, 비워 내기 쉬운 것):
- 5 데이터 흐름: "입력 한 행(예: ○○ 기록)이 정제 → 계산 → 선택 → 내보내기까지 어떻게 이어지나? 확인할 함수는?"
- 6 결과 이상 진단: "운영 중 '○○인데 △△'라는 보고가 왔다. 어디부터 의심하고, 무엇으로 확인하고, 고친 뒤 무엇으로 다시 검증하나?"
- 1 설계 근거: "문서와 코드는 ○○(가중치·방법)을 씁니다. 이유와 버린 대안은?"
- 3 동시성·운영: "A가 ○○하는 동안 B가 △△하면 실제로 어떤 일이? 사용자가 보는 결과는 어느 버전인가?"

**시간이 남으면 2개**:
- 2 확인·가정: "담당자가 ○○을 확답하지 못했습니다. 무엇이 사실이고 무엇이 가정이며, 틀리면 무엇을 다시 검증하나?"
- 4 AI 협업 추궁: AI 협업 문서의 문장 하나를 그대로 인용 + "어떻게 검증했나?"

## 2. 한 문항씩 진행 (문항당 약 5분)
1. 질문만 낸다. 힌트·모범 답을 먼저 주지 않는다. "붙여넣기 없이 직접 치세요."
2. 사용자가 답하면 4칸으로 판정한다: **결론** / **코드 지점(함수·파일 하나)** / **실제 숫자 하나** / **영향받는 결과 + 다음 검증**. 칸마다 ○·△·×.
3. 사용자 답이 구현과 다르면 그것부터 알린다(파일:줄 근거).
4. 빠진 칸만 짚고 **고쳐 쓰게** 한다. 두 번째 답 뒤에 모범 답(5문장 이내)을 보여 준다.
5. 사용자가 "모르겠어"면: 6줄 이내로 설명 → 같은 질문을 다시 낸다. 설명만 하고 넘어가지 않는다.
6. 틀렸던 내용은 GUIDE.md 7절 "헷갈리기 쉬운 것"에 `오해 → 사실`로 추가한다.
- 사용자가 "다음", "그만"이라고 하면 바로 따른다.

## 3. 빈 답 방지 (마지막 3분)
- 아래 틀을 사용자가 한 번 직접 쳐 보게 한다. 시험에서 모르는 문항이 나와도 이 틀로 채운다.
  > "결론: ○○입니다. 근거: △△ 함수가 □□를 합니다(숫자 n). 영향: 이게 틀리면 ◇◇가 바뀝니다. 확인: ☆☆을 다시 돌려 보겠습니다."
- 모르는 부분은 "확인하지 않았다. 확인하려면 ○○을 본다"로 쓴다. "ㅇ", "."처럼 비워 내지 않는다.

## 4. 마무리 커밋 (사용자가 "마무리"라고 하거나 연습이 끝났을 때)
- 경로를 지정해 커밋한다: GUIDE.md, MEMO.md, `.agents/`, `evidence/`, 과제 문서. 메시지 `explain: 서술형 연습·GUIDE 갱신 / 제출 전 정리`.
- `git status`가 비었는지 확인하고, 남은 파일이 있으면 목록을 보여 준다(원본 데이터·`runtime/`은 제외 대상인지 확인).
- 안내: "제출 직전에 GUIDE.md 0절·9절과 MEMO.md만 한 번 더 읽으세요."
