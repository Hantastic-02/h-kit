# kit-fix — 모아서 한 번에 고치기

## 1. 받은 것 분류 (표 하나로 보여 주고 바로 진행)
입력: 사용자 메모, REVIEW.md에 사용자가 적은 칸, `evidence/check-report.md`(있으면), 담당자 새 답·변경 요청(있으면 원문 그대로 PLAN 5절과 DECISIONS.md 변경 기록에 추가).

| 번호 | 내용 | 종류 | 할 일 |
|---|---|---|---|
- 종류: **고장**(실행 안 됨·데이터 훼손) / **규칙 위반·담당자 조건 누락** / **요구 누락·변경 요청** / **정상인데 오해** / **새 아이디어**
- 이 순서로 고친다. 사용자가 시간이 없다고 하면 앞의 둘만.
- "정상인데 오해"는 코드를 고치지 않는다. README·담당자 원문 근거로 설명하고 REVIEW.md 기대 결과에 한 줄 추가한다.
- 사용자 의견이 README와 충돌하면 고치지 말고 README 줄을 인용해 알린다.
- 큰 구조 변경이 필요한 항목은 "크게 바꿔야 함 — 대신 ○○(작은 방법)"을 표에 함께 적고 작은 방법으로 진행한다.

## 2. 고치기
- PLAN.md 7절 끝에 `### G. 수정` 블록을 만들고 위 표를 `- [ ] G01 …` 항목으로 옮긴다.
- kit-build "항목 하나를 할 때" 규칙 그대로: 실행해서 확인 → `[x]` + 커밋. 중간에 멈추지 않는다.
- 고친 곳마다 그 문제를 다시 만드는 테스트를 하나씩 더한다. 담당자 조건이면 E1 독립 검사에도 넣는다.
- 변경 요청이면 영향받은 결과의 전후 숫자를 DECISIONS.md 변경 기록에 적는다.

## 3. 재검사 (필수)
- 전체 테스트, E1 독립 검사, 실행 안내 그대로 시작 → 헬스체크를 다시 돌린다. 숫자를 PLAN·HANDOFF에 갱신한다.

## 4. 문서 갱신
- 바뀐 코드에 맞춰 DECISIONS.md, REVIEW.md, GUIDE.md(파일:줄·숫자·10절 답), 과제가 요구한 문서를 고친다. HANDOFF.md 갱신.
- 고친 것 중 의미 있는 것은 GUIDE.md 10절 "처음 만든 것에서 틀려서 고친 것" 답에 한 줄 더한다.

## 5. 보고 (채팅)
1. 고친 것 / 고치지 않은 것(이유) 표
2. 재검사 숫자
3. 사용자가 다시 볼 것 1~3개
- 커밋: `fix: n건 / 확인: 테스트 n passed, 독립 검사 위반 n`.
- 두 번째 `$kit-fix`부터는 고장과 규칙 위반만 받는 것을 권한다(사용자가 원하면 예외).
