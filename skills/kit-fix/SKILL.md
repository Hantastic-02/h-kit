# kit-fix — 모아서 한 번에 고치기

## 1. 받은 것 분류 (표 하나로 보여 주고 바로 진행)
입력: 사용자가 붙여 넣은 메모, REVIEW.md에 사용자가 적은 칸, `evidence/check-report.md`(있으면), 담당자 새 답(있으면 원문 그대로 PLAN 4절에 추가).

| 번호 | 내용 | 종류 | 할 일 |
|---|---|---|---|
- 종류: **고장**(실행 안 됨·데이터 훼손) / **규칙 위반·담당자 조건 누락** / **요구 누락** / **정상 동작인데 오해**(README 근거로 설명만) / **새 아이디어**
- 이 순서로 고친다. 사용자가 시간이 없다고 하면 앞의 둘만.
- "정상 동작인데 오해"는 코드를 고치지 않는다. GUIDE.md 7절 "헷갈리기 쉬운 것"과 REVIEW.md 기대 결과에 한 줄 추가한다.
- 사용자 의견이 README와 충돌하면 고치지 말고 README 줄을 인용해 알린다.
- 큰 구조 변경이 필요한 항목은 "고치는 데 큼 — 대신 ○○(작은 방법)"을 표에 함께 적고 작은 방법으로 진행한다.

## 2. 고치기
- PLAN.md 7절 끝에 `### G. 수정 (kit-fix)` 블록을 만들고 위 표를 항목으로 옮긴다(`- [ ] G01 …`).
- kit-build의 "항목 하나를 할 때" 규칙 그대로: 실행해서 확인 → `[x]` + 커밋. 중간에 멈추지 않는다.
- 고친 곳마다 그 문제를 다시 만드는 테스트를 하나씩 더한다. 담당자 조건이면 E1 독립 검사에도 넣는다.

## 3. 재검사 (필수)
- 전체 테스트, E1 독립 검사, E2 실행 안내 그대로 시작 → `/health`를 다시 돌린다. 숫자를 PLAN·HANDOFF에 갱신한다.
- 내보내기 결과가 바뀌었으면 E1 숫자도 바뀌었는지 확인한다.

## 4. 문서 갱신
- 바뀐 코드에 해당하는 GUIDE.md 카드·9절 서술형 카드·8절 숫자를 고친다. 실행 안내가 바뀌었으면 과제 문서도.
- 사용자가 AI 결과를 고친 일이 있었으면 AI 협업 문서 초안에 근거(MEMO 줄·커밋)와 함께 추가할지 제안한다.
- HANDOFF.md 갱신.

## 5. 보고 (채팅)
1. 고친 것 / 고치지 않은 것(이유) 표
2. 재검사 숫자
3. 사용자가 다시 볼 것(있으면 1~3개만)
4. "이제 기능을 멈추고 공부할 때입니다. GUIDE.md 0절·9절부터 읽고, 새 터미널에서 `$kit-explain`으로 서술형을 연습하세요."
- 커밋: `fix: n건 / 확인: 테스트 n passed, 독립 검사 위반 0` (`evidence/check-report.md` 포함).
- 두 번째 `$kit-fix`는 고장과 규칙 위반만 받는 것을 권한다(사용자가 원하면 예외).
