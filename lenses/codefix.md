# 렌즈: 기존 코드 수정

## 함정 관점
- 테스트가 통과해도 명세상 틀린 곳(테스트가 다루지 않는 경계·입력)
- 기존 테스트가 고정한 기대값이 명세와 다른 경우: 기존 테스트는 고치지 않고 차이를 보고·기록
- 고친 함수를 부르는 다른 곳(부작용), 출력 형식·실행 명령·파일 이름은 그대로
- 숨은 원인이 여러 개인 경우: 하나 고치고 멈추지 않는다
- 데이터 쪽 원인(시간대·단위·중복)과 코드 쪽 원인 구분

## 사용 질문 (2개 고른다)
- 이 코드의 결과를 누가 어디에 쓰나요? 결과가 바뀌면 누가 영향을 받나요?
- 바꾸면 안 되는 출력 형식·동작이 있나요? 원하는 결과물은 무엇인가요(수정 코드·비교표·테스트)?

## 기대값 출처
- 원인마다 먼저 실패하는 테스트로 재현(FAIL) → 고친 뒤 PASS. 기대값은 명세 문장·담당자 원문에서
- 변경 전후 결과 비교표(어떤 행·건수가 바뀌었나)

## 사용 시나리오 (새 세션 검토)
- 지정 실행 명령을 처음부터 실행해 출력 파일을 실제로 열어 본다
- 다른 데이터(같은 형식)로 실행

## 서술형 단골
- 원인을 모두, 각각의 수정 위치와 확인 방법, 고치지 않은 것과 이유
- 변경 전후 숫자가 몇 건 바뀌었고 왜
