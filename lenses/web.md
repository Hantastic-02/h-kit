# 렌즈: 웹 서비스·화면

## 함정 관점
- 기존 버그: 상태 계산(마지막 행 기준·정렬 안 함), 시간대 표시, 기준 시각(now) 고정 옵션, 바인딩 주소(0.0.0.0)
- API 계약: 필드 이름·형식(시각 형식, 소수 자리, 반올림 방식), 파라미터 없음·빈 값, count 일치
- 요약과 목록: 필터가 요약에 영향을 주나, 같은 기준으로 계산하나
- 다른 입력 파일로 실행해도 동작하나

## 웹 점검표 (kit-plan에서 PLAN 할 일로 옮기고, 새 세션 검토에서 하나씩 실제로 확인)
- [ ] 서버가 지정 명령 그대로 뜨고 0.0.0.0에 바인딩된다
- [ ] 화면에 기준 시각(어느 시점의 데이터인지)과 시간대(KST 등)가 보인다
- [ ] 필터·선택이 주소창 URL에 남는다(쿼리 문자열 갱신)
- [ ] 그 URL을 새 탭에서 열면 같은 필터가 복원된다(링크 공유)
- [ ] 새로고침해도 필터가 유지된다
- [ ] 결과가 0건이면 "조건에 맞는 항목 없음"이 보이고, 통신 오류와 구분된다
- [ ] 서버 오류·통신 실패 시 화면에 오류 안내가 보인다(빈 표로 숨지 않음)
- [ ] 긴급·이상 건 강조가 눈에 띄고, 정렬 기준이 요구와 같다
- [ ] 요약 숫자와 목록 건수가 같은 기준으로 맞는다(필터 적용 여부 포함)
- [ ] 같은 형식의 다른 데이터로 서버를 다시 띄워도 화면이 정상이다
- 링크 공유 구현 확인은 코드 검색이 아니라 실제로 URL을 복사해 새 탭에서 열어서 한다(`URLSearchParams`가 있다고 공유가 되는 것은 아니다).

## 사용 질문 (2개 고른다, 영향 건수가 없어도 반드시 보낸다)
- 누가 언제 이 화면을 열고, 처음에 무엇부터 보나요?
- 화면에서 본 내용을 다른 사람에게 어떻게 전달하나요(링크·캡처·회의 자료)?
- 자주 쓰는 조합이나 꼭 있어야 하는 버튼·표시가 있나요?

## 기대값 출처
- 과제 문서의 API 예시(예시 값이 규칙과 모순되면 숨은 기준의 단서), 담당자 원문, 손계산 1건

## 사용 시나리오 (새 세션 검토에서 실제로 해 본다)
처음 열기 → 기준 시각·요약·목록 숫자 확인 → 필터 조합 → 링크를 복사해 새 탭에서 열기 → 새로고침 → 빈 결과 → 서버를 끈 상태에서 새로고침 → 다른 데이터로 서버 재실행

## 서술형 단골
- 화면 숫자가 다른 시스템 숫자와 다를 때 이유와 확인 방법
- 처음 코드가 틀렸던 원인을 모두, 각각 어떻게 고치고 무엇으로 확인했나
- 기준 변경 요청 시 고칠 곳(파일:줄)과 숫자 변화
