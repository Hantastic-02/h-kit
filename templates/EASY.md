     쉬운 설명 = 쉬운 단어 + 정돈된 논리 순서 + 실제 예시로 끝까지 따라가기. 비유는 그다음이고, 없어도 된다. -->

## 기준
읽은 사람이 그 절이 답하는 질문에 **자기 말로 세 문장 안에 답할 수 있어야** 한다. 서술형 시험에서 그대로 쓸 수 있으면 성공이다.

## 설명 수순 (절마다, 또는 복잡한 개념마다 이 순서)
1. **질문**: 이 부분이 답하는 질문을 한 문장으로 쓴다. 예: "두 운영자가 동시에 작업하면 어떻게 되나?"
2. **결론**: 답을 먼저 한두 문장으로 쓴다.
3. **왜 필요한가**: 이게 없으면 무슨 일이 생기는지, 이번 과제의 실제 상황으로 쓴다.
4. **어떻게 동작하나**: 몇 단계인지 먼저 말하고("세 단계입니다") 번호 목록으로 쓴다. 단계마다 `무엇을 받아 → 무엇을 해서 → 무엇이 나온다`.
5. **실제 예 하나 따라가기**: 이번 과제의 실제 한 건(한 사람, 한 행, 한 요청)이 4번의 단계를 지나며 어떤 값이 되는지 숫자로 끝까지 보여 준다. **이 단계가 설명의 중심이다.**
6. **경계와 한계**: 언제 안 되는지, 무엇을 가정했는지, 가정이 틀리면 무엇이 바뀌는지.
7. **한 줄로 말하면**: 2번 결론을 한 번 더, 더 짧게.

쉬운 부분은 1·2·7만 써도 된다. 어려운 부분(계산식, 정제 규칙, 동시 작업, 오류 처리, 최적화 방법)은 1~7을 다 쓴다. **어려운 부분을 쉬운 부분보다 짧게 쓰지 않는다.**

## 규칙 8개
1. **논리 순서를 지킨다.** 전체 → 부분, 원인 → 결과, 입력 → 처리 → 출력 순서로 쓴다. 독자가 "그래서 그다음은?"을 묻게 되는 빈 단계를 남기지 않는다.
2. **문장 사이를 연결어로 잇는다.** "그래서", "왜냐하면", "만약 ~이면", "그 결과", "대신" 같은 말로 앞 문장과의 관계를 드러낸다. 짧은 문장을 끊어 나열만 하면 논리가 사라진다. 한 문장에는 한 가지 내용만 담고, 60자를 크게 넘지 않는다.
3. **단어는 아래 "단어 고르기"를 따른다.** 사무실에서 실제로 쓰는 말을 쓰고, 새 말을 지어내지 않는다. 한 번 정한 말은 끝까지 같은 말로 쓴다(자료/데이터셋/묶음처럼 섞지 않는다).
4. **코드 이름(함수·파일·변수)은 설명 본문에 쓰지 않는다.** 단, "어디서 보나" 표, GUIDE 1절 흐름 표, GUIDE 9절 서술형 카드, 서술형 연습 질문과 모범 답에는 **반드시** 쓴다(서술형은 "어느 함수에서"를 묻는다).
5. **계산은 식 + 숫자 대입으로 보여 준다.** "같은 비중으로 평균낸다"에서 멈추지 않는다. 실제 항목 하나의 요소 값을 넣어 결과 숫자까지 계산해 보인다.
6. **숫자는 실제 값과 단위로 쓴다.** "많이"가 아니라 "1,250건", "34분".
7. **"왜"를 붙이고, 버린 방법도 쓴다.** 무엇을 했는지 다음에 왜 그렇게 했는지, 다른 방법을 왜 안 썼는지를 쓴다.
8. **비유는 선택이고, 쓸 때는 조건이 있다.**
   - 실제 예시(수순 5번)로도 이해가 어려운 개념에만 쓴다. 절 첫머리를 여는 장식용으로 쓰지 않는다.
   - 비유의 부분이 실제 구조와 하나씩 대응해야 한다. 대응을 한 줄로 밝힌다. 예: "은행 번호표 = 버전 번호, 창구 = 저장 기능".
   - 비유가 어긋나는 지점을 한 줄 적는다.
   - 비유를 쓴 뒤에도 수순 4·5(실제 단계와 실제 예)를 생략하지 않는다.
   - 한 절에 비유는 최대 하나.

## 단어 고르기
쉬운 말 = **비개발자 회사원이 이미 아는 말**이다. 영어를 피하려고 지어낸 우리말은 오히려 더 어렵다.
1. **흔한 외래어는 그대로 쓴다.** 버전, 데이터, 파일, 서버, 로그인, 비밀번호, 화면, 버튼, 새로고침, 저장, 테스트, 오류, 백업. 이것을 "판수", "출입증", "서랍" 같은 말로 바꾸지 않는다.
2. **새 말을 지어내지 않는다.** 일상에서 그 뜻으로 쓰지 않는 조합("판수가 낡았다", "통째 저장", "눈금 맞춤", "운영 바탕")은 금지. 처음 보는 사람이 되묻게 된다.
3. **정식 용어는 숨기지 않는다.** 서술형에서 그대로 쓸 말(트랜잭션, 잠금, 정규화, 버전 충돌)은 처음 한 번 "쉬운 설명(정식 용어)"로 소개하고, 그 뒤로는 정식 용어를 쓴다. 정식 용어를 다른 우리말로 바꿔 부르지 않는다.
4. **사람이 보고 하는 일로 쓴다.** 내부 상태 대신 화면에서 무엇을 누르고 무엇이 뜨는지로 쓴다. "판수가 낡으면 거절" 대신 "내가 화면을 연 뒤 다른 사람이 먼저 저장했다면, 저장 버튼을 눌렀을 때 '다른 사람이 먼저 바꿨습니다. 새로고침하세요'가 뜹니다."
5. **명사만 이어 붙이지 않는다.** "확정 버전 보존. 발주 연동은 범위 밖"처럼 끊지 말고 "확정한 결과는 버전째로 남깁니다. 발주 시스템과 연결하는 일은 이번 과제 범위가 아니라서 하지 않았습니다"처럼 주어와 서술어가 있는 문장으로 쓴다. 표 칸도 짧되 문장으로 읽혀야 한다.
6. **사용자에게 필요 없는 내부 사정은 빼거나 결과로 말한다.** "연결을 닫지 않아 첫 시험의 정리가 실패" → 필요하면 "첫 테스트가 실패해서 원인을 고쳤고, 다시 돌려 통과했습니다".
7. **줄임말·내부 약칭을 만들지 않는다.** "기본본·재계산본" 대신 처음에 "기본 결과(원래 데이터로 만든 것)", "재계산 결과(특정 날짜부터 다시 만든 것)"처럼 풀어 쓰고, 그 이름을 계속 쓴다.

**바꿔 쓰기 표** (AI가 자주 지어내는 말)
| 쓰지 말 것 | 이렇게 쓴다 |
|---|---|
| 판수, 판 번호, 판수가 낡았다 | 버전, 버전 번호 / "내가 연 뒤 다른 사람이 먼저 저장했다" |
| 증표, 출입증 | 로그인 상태(로그인 토큰) |
| 통째 저장·되돌림 | "전부 저장되거나, 실패하면 하나도 저장되지 않는다(트랜잭션)" |
| 눈금 맞춤 | 점수 환산(정규화). 예: 10점 만점 8점 → 5점 만점 4점 |
| 계속 남는 저장소, 장부, 서랍 | 데이터베이스(DB) |
| 상태 확인, 가게 영업등 | 서버 상태 확인 주소(헬스체크) |
| 자료 한 묶음, 꾸러미 | 데이터셋(입력 파일 한 세트) |
| 검수대 | 데이터 검사 |
| 작업 중 표시, 화장실 사용 중 표시 | 잠금 / "다른 작업이 끝날 때까지 기다리라는 안내가 뜬다" |
| 운영 바탕 | 실행 환경(서버·DB·설정) |
| 의미 시험 | 테스트 |

## 쓴 뒤 점검 (스스로 확인하고 고친다)
- 절마다 "질문"이 있나? 그 질문에 세 문장으로 답해 보면 막히는 곳이 있나?
- 비유를 지워도 이해되나? 그렇다면 비유를 지운다.
- 어려운 부분에 단계 목록과 실제 예 따라가기가 있나?
- 계산이 식에서 멈추지 않고 실제 숫자까지 갔나?
- 문장 사이에 연결어 없이 툭 끊긴 곳이 있나?
- 같은 대상을 다른 말로 부른 곳이 있나?
- 이 단어를 사무실 동료에게 그대로 말하면 되묻지 않을까? 되물을 것 같으면 바꿔 쓰기 표를 본다.
- 지어낸 말, 명사만 이어 붙인 줄, 내부 약칭이 있나?

## 예시 — 동시 작업 설명

**나쁨**
> 공동 장부를 한 사람씩 고치는 방식입니다. 데이터 적용·결과 생성·확정은 동시에 실행하지 않습니다. 다른 작업이 진행 중이면 다시 시도하라고 알립니다. 화면의 판수가 낡았으면 변경 요청을 거절합니다.
>
> (문제: 장식 비유, 끊긴 나열, 지어낸 말 "판수가 낡았다", 실제로 무슨 일이 일어나는지 없음)

**좋음** (질문 → 결론 → 왜 → 단계 → 실제 예 → 한계)
> **질문**: 운영자 A가 새 데이터셋을 적용하는 동안 운영자 B가 결과 재계산을 누르면 어떻게 되나?
> **결론**: B의 재계산은 거절되고 "다른 작업이 끝날 때까지 기다려 주세요"가 뜹니다. 적용이 끝난 뒤 B가 새로고침하고 다시 누르면, 새 데이터셋 기준으로 재계산됩니다.
> **왜**: 만약 둘이 동시에 돌면, 재계산이 옛 데이터 절반과 새 데이터 절반을 섞어 읽을 수 있습니다. 그러면 어느 데이터로 만든 결과인지 아무도 설명할 수 없습니다.
> **어떻게** (장치가 두 개입니다):
> 1. **잠금**: 데이터셋 적용·재계산·확정은 한 번에 하나만 실행됩니다. 하나가 도는 중에 다른 것을 누르면 서버가 바로 거절합니다.
> 2. **버전 확인**: 데이터셋을 적용할 때마다 버전 번호가 1씩 올라갑니다. 화면은 처음 열 때 받은 버전 번호를 기억해 두었다가, 저장할 때 함께 보냅니다. 서버는 그 번호가 지금 번호와 다르면 "다른 사람이 먼저 바꿨습니다. 새로고침하세요"로 거절합니다.
> 그리고 확정한 결과에는 어느 버전의 데이터로 만들었는지가 함께 저장됩니다. 그래서 사용자가 보는 결과가 어느 데이터 기준인지 항상 알 수 있습니다.
> **실제 예**: 14:02 A가 데이터셋 적용을 누릅니다. 14:03 B가 재계산을 누르면 잠금 때문에 거절됩니다. 14:04 적용이 끝나 버전이 7에서 8이 됩니다. B의 화면은 아직 버전 7을 기억하고 있어서, 그대로 저장하면 버전 확인에서 거절됩니다. B가 새로고침하면 버전 8을 받고, 그때 재계산이 됩니다. 일반 사용자는 그동안 버전 7로 만든 기존 확정 결과를 계속 봅니다.
> **한계**: 같은 결과를 두 사람이 동시에 고치면 먼저 저장한 쪽만 남습니다. 두 사람의 수정을 합쳐 주는 기능은 없습니다.
> **한 줄로 말하면**: 한 번에 하나만 실행하고(잠금), 내가 연 뒤 바뀐 데이터에는 저장을 막아서(버전 확인) 데이터가 섞이지 않게 합니다.
